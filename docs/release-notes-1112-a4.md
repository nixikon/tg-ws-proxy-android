## 1.11.2-a4

Исправление после перевыпуска релизов: если сборка из кэша больше не опубликована, приложение зацикливалось на ошибке «HTTP 404».

- **Что было не так.** Приложение запоминает найденный релиз (версию, имя файла, размер и хеш) и на следующем запуске показывает его сразу, не дожидаясь сети — в том числе в уведомлении с кнопкой «Скачать». Если релиз после этого удалён или перевыпущен под другим тегом, ссылка из кэша начинает отдавать 404, и «Скачать» снова и снова заканчивается ошибкой.
- **Что исправлено.** На 404 при скачивании кэш сбрасывается, и приложение тут же перепроверяет релизы: если есть актуальная сборка, предложение обновиться появляется заново, а сообщение объясняет, что произошло.
- **Почему вы это увидели.** В кэше остался *временный* релиз `1.11.2-a4`: он публиковался на несколько минут для проверки резервного пути обновления и затем был удалён. Отсюда «Не удалось скачать: HTTP 404 while downloading TgWsProxy-1.11.2-a4-android.apk». Теперь `1.11.2-a4` — обычный релиз, поэтому и ссылка из кэша снова рабочая.
- **Что сделать.** Закройте и снова откройте приложение (при запуске оно перепроверит релизы и обновит кэш), затем нажмите «Скачать и установить». Если не хочется ждать — можно поставить APK вручную со страницы релиза.
- **Остальное — как в `1.11.2-a3`:** исправленный резервный путь проверки обновлений (через ленту релизов), проверка кэша загрузки по SHA-256, проверка скачанного файла перед установкой. Ядро `1.11.2` и настройки не менялись.

Пакет `com.nixikon.tgwsproxy`, версия `1.11.2-a4` (versionCode 20), ABI `arm64-v8a` + `x86_64`.

Обновление ставится поверх `1.11.1-a1`, `1.11.2-a1`, `1.11.2-a2` и `1.11.2-a3`.
