## 1.11.0-a9

Убрано ложное сообщение об ошибке, которое появлялось при запуске прокси с плитки в «быстрых настройках».

- **Что было видно.** На планшете нажатие плитки открывало приложение и показывало диалог «Не удалось запустить прокси: Непредвиденная ошибка: startForegroundService() not allowed due to mAllowStartForeground false: service com.nixikon.tgwsproxy/.ProxyService». Выглядело как сбой, хотя приложение в этот момент уже поднимало прокси из своего окна.
- **В чём причина.** С Android 12 система запрещает запускать foreground-сервис из фона, а плитка — не активность, поэтому на части прошивок запуск отклоняется (на других устройствах тот же запуск проходит). Обход в приложении есть с ранних версий: плитка открывает приложение, и оно запускает прокси из активного окна. Ошибкой было другое — отказ системы попадал в очередь ошибок интерфейса и показывался модальным диалогом с сырым английским текстом исключения.
- **Что изменилось.** Запрет фонового запуска теперь распознаётся отдельно и пишется только в лог, а приложение, открытое плиткой, показывает одну короткую подсказку: «Система не разрешила фоновый запуск — включаю прокси из приложения». Диалог с сырым текстом исключения больше не появляется; если служба действительно не запустилась по другой причине, диалог остаётся, но объясняет, что делать, на языке интерфейса (RU/EN).
- **Если плитка на вашем устройстве всегда открывает приложение.** Это политика системы, а не ошибка приложения. Проверьте, что фоновой работе ничего не мешает: «Настройки» → «Батарея» → «Без ограничений» для TG WS Proxy (в приложении для этого есть переключатель «Игнорировать оптимизацию батареи» в разделе «Автозапуск»).

Пакет `com.nixikon.tgwsproxy`, версия `1.11.0-a9` (versionCode 15), ABI `arm64-v8a` + `x86_64`.

Обновление ставится поверх `a8`.
