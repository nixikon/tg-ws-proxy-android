## 1.11.2-a2

Исправление обновления: APK из `1.11.2-a1` не устанавливался поверх предыдущих версий.

- **Что было не так.** Сборка `1.11.2-a1` была подписана другим ключом, чем все релизы до неё: в сборочном окружении не был указан каталог с ключом форка, и Gradle создал новый отладочный ключ. Android не ставит обновление, если сертификат отличается от сертификата установленного приложения, — файл скачивался, установщик открывался и выдавал ошибку. Ядро прокси и сама версия 1.11.2 к этому отношения не имеют.
- **Ассет `1.11.2-a1` перевыпущен** 18.10.2026 с правильным ключом — тем же, что у `1.11.0-a9` и `1.11.1-a1` (SHA-256 сертификата `ab887caa…`). Заново скачанный APK ставится поверх `1.11.1-a1`.
- **Повторная попытка больше не берёт старый файл из кэша.** Приложение переиспользовало `cache/update.apk`, если совпадал только размер файла, — а у перевыпущенного ассета размер тот же, поэтому повторное нажатие «Обновить» снова отдавало установщику сломанный файл. Теперь кэш принимается, только если SHA-256 файла совпадает с хешем ассета из релиза; иначе файл скачивается заново.
- **Почему `a2`, а не пересборка `a1`.** Версия должна вырасти, чтобы обновление было предложено тем, у кого установлена `1.11.1-a1`. APK `a2` к тому же немного больше (39998099 против 39998035 байт — в него добавлен файл лицензии `assets/LICENSE.txt`), поэтому старая проверка кэша по размеру в уже установленных сборках не сработает и файл скачается заново автоматически.
- **Если обновление уже пыталось скачаться** (в кэше лежит файл от `1.11.2-a1`): просто нажмите «Обновить» ещё раз — теперь скачается `a2` и установится. Если по какой-то причине не скачивается, очистите кэш приложения (Настройки → Приложения → TG WS Proxy → Память → Очистить кэш) или поставьте APK вручную по ссылке из релиза.
- **Если `1.11.2-a1` у вас уже установлен** (это возможно только на чистом устройстве: поверх прошлых версий он не ставился), то `a2` поверх него не встанет — сертификаты разные. Удалите приложение и поставьте `a2` заново; настройки и secret при этом не сохранятся, ссылку-подключение нужно будет добавить в Telegram заново.
- **Проверки сборки.** `tools/verify_apk.py` теперь сверяет сертификат APK с ключом форка и падает, если он другой, а также следит, чтобы в APK не попал кэш байткода; `tools/build_apk.py` собирает APK с нужным каталогом ключа и печатает отпечаток сертификата.
- **Что проверено на эмуляторе.** Установлена `1.11.1-a1`, затем поверх неё поставлен APK из `1.11.2-a1` — платформа отказывает ровно так, как это видел пользователь: `INSTALL_FAILED_UPDATE_INCOMPATIBLE: Existing package com.nixikon.tgwsproxy signatures do not match newer version; ignoring!`. После этого приложение обновило себя само через свой диалог и системный установщик до `1.11.2-a2` (versionCode 18).
- **Ядро не изменилось.** `1.11.2`: 13 из 15 файлов `proxy/` байт-в-байт совпадают с апстримом, настройки, secret и ссылка-подключение те же.

Пакет `com.nixikon.tgwsproxy`, версия `1.11.2-a2` (versionCode 18), ABI `arm64-v8a` + `x86_64`.

Обновление ставится поверх `1.11.1-a1` и `1.11.2-a1`.
