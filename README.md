# TG WS Proxy для Android — форк

Android-версия (APK) прокси **[tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy)**
автора **Flowseal**.

Это **форк**: движок прокси и оригинальное десктопное приложение написал Flowseal,
здесь к нему добавлена Android-оболочка (интерфейс на Kotlin, foreground-сервис,
плитка в быстрых настройках, встроенные обновления) и встроенный CPython через
[Chaquopy](https://chaquo.com/chaquopy/). Ядро прокси оставлено таким же, как в
апстриме, — обновления оригинала подтягиваются почти механически.

Локальный MTProto-прокси: трафик Telegram идёт через WebSocket, работает только
на устройстве — без сторонних серверов и подписок.

APK подписан отладочным ключом Android и ставится напрямую. Пакет —
`com.nixikon.tgwsproxy`, ABI — `arm64-v8a` и `x86_64`, минимальная версия —

> вторая копия; старую нужно удалить вручную. Настройки и secret не переносятся.

## Установка

1. Скачайте APK из Releases.
2. Разрешите установку из этого источника (Android спросит один раз).
3. Откройте приложение, нажмите **Запустить**.
4. Нажмите **Открыть в Telegram** — прокси добавится в список подключений.
5. Приложение предложит отключить оптимизацию батареи: это нужно, чтобы система
   не усыпляла прокси в фоне.

Пока прокси работает, рядом с часами виден значок «T», а в «быстрых настройках»
есть плитка для включения и выключения без открытия приложения. Новые версии
приложение проверяет само: сообщает сразу при запуске, а если прокси запущен
плиткой — присылает уведомление с кнопкой «Скачать».

## Возможности

- локальный MTProto-прокси с передачей трафика через WebSocket;
- мультиплексирование медиа по HTTP/2 через Cloudflare;
- поддержка собственного CF-прокси и CF Worker, проверка доступности доменов;
- настройки: порт, secret с перегенерацией, отображение DC → IP, размер пула,
  буфер, размер и ротация лога, fake TLS;
- плитка в «быстрых настройках», уведомление с действиями «Открыть в Telegram» и
  «Перезапустить»;
- автозапуск при загрузке, работа в фоне через foreground-сервис, отключение
  оптимизации батареи;
- статистика в реальном времени, журнал, диагностика (включая проверку прямого
  доступа к серверам Telegram);
- русский и английский интерфейс, тёмная и светлая темы;
- встроенные обновления из этого репозитория.

## Чего не будет: звонки

**Голосовые и видеозвонки, а также войс-чаты через MTProto-прокси не работают** —
это архитектурное ограничение протокола, а не недоделка приложения: медиа звонка
идёт отдельным потоком по UDP (WebRTC) мимо прокси, и перенести его через
WebSocket нельзя. В актуальном Telegram для Android переключателя «звонки через
прокси» нет, то есть клиент вообще не отдаёт звонок прокси: прокси звонкам не
мешает, но и помочь не может. То же самое написано в FAQ оригинального проекта.

Что помогает: отключить прокси на время звонка или использовать для звонков VPN
(он переносит UDP). Сообщения, файлы, видео и голосовые сообщения работают.
Проверить, закрыт ли прямой доступ к серверам Telegram, можно строкой `call path`
в «Диагностике» приложения.

## Исходники и сборка

```
android/                     проект Gradle
  app/src/main/
    java/com/nixikon/tgwsproxy/   Kotlin: активности, сервис, плитка, обновления
    python/
      android_entry.py       мост Kotlin ↔ Python
      proxy/                 ядро прокси из апстрима (12 из 14 файлов не тронуты)
      utils/                 пути, логи, диагностика, проверки связности
      certs/cacert.pem       встроенное хранилище корневых сертификатов
    res/values, res/values-ru  каталоги строк EN / RU
tools/                       вспомогательные скрипты: проверка APK, e2e-тест,
                             MTProto-зонд, управление интерфейсом эмулятора
docs/release-notes-*.md      тексты релизов
```

Требования: **JDK 17**, **Android SDK** с platform 36 и build-tools 36, интернет
при первой сборке (Gradle тянет AGP, Kotlin, AndroidX и рантайм Chaquopy, а
Chaquopy — пакеты `httpx[http2]` из pip).

```powershell
$env:JAVA_HOME    = "C:\path\to\jdk17"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"

cd android
.\gradlew.bat :app:assembleRelease    # или ./gradlew на Linux/macOS
# результат: app\build\outputs\apk\release\app-release.apk
```

Дополнительные материалы по внутреннему устройству (архитектура, ревизии
изменений, что проверено на устройстве и как именно) — в [README.en.md](README.en.md).

### Отличия ядра от апстрима

Из 14 файлов пакета `proxy/` **12 побайтово совпадают с апстримом 1.11.0**;
адаптированы только два:

| Файл | Что изменено |
| --- | --- |
| `proxy/_aes.py` | AES-CTR считается через `javax.crypto.Cipher` по мосту Chaquopy (нативная скорость, без зависимостей). Бэкенд проверяется на векторе NIST SP 800-38A F.5.1 при импорте, включая пошаговые `update()` |
| `proxy/utils.py` | Вместо `certifi` — настраиваемый поиск CA-бандла (в том числе системного хранилища Android) плюс правка `ws_domains` из 1.11.0 |

В `utils/` не тронут `logging_setup.py`; `default_config.py` и `diagnostics.py`
потеряли импорты tkinter/i18n (локализация переехала в Kotlin), `update_check.py`
удалён вместе с десктопной проверкой обновлений. `app_paths.py` и
`connectivity.py` — новые.

Проверка собранного APK (совпадение Python-исходников, целостность CA-бандла,
наличие нативных библиотек и строк обоих языков):

```powershell
python tools\verify_apk.py android\app\build\outputs\apk\release\app-release.apk android\app\src\main\python
```
